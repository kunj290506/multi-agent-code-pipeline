LAYOUT REQUIREMENTS

- Left panel: a file explorer tree showing the live project folder 
  structure. It must update automatically as agents create or modify 
  files during a run.
- Center panel: a code viewer that opens automatically to show the 
  content of any file the agents are currently writing or have just 
  written, with syntax highlighting.
- Right panel or bottom panel: a chat window where the user types a 
  feature request in plain language and submits it.
- Below or alongside the chat input: a live reasoning/activity feed 
  that shows, step by step, what is happening — which agent is running, 
  what it received as input, what it produced as output, and whether a 
  step passed or failed. This must update in real time as the pipeline 
  runs, not only after completion.

FUNCTIONAL REQUIREMENTS

- On submitting a feature request in the chat window, the backend must:
  1. Call the Planner agent to get the subtask list.
  2. Execute each subtask against the correct downstream agent, in 
     dependency order.
  3. Stream each step's status and output to the frontend in real time 
     (use WebSockets or server-sent events, not polling).
  4. When the Code-Gen agent produces a file, write it to the actual 
     target-app/ directory (or a clearly separate generated-output/ 
     directory if writing into target-app/ is judged unsafe) and 
     immediately reflect this in the file explorer and code viewer.
  5. Route generated code through the Reviewer agent and display the 
     pass/fail result and any issues in the reasoning feed.
  6. If a query needs to run through the DB agent, show the generated 
     query, then the execution result, in the reasoning feed.

  (for example: "Planner", "RAG", "Code-Gen", "Reviewer", "DB Agent")

  outcomes remain visible after a new request is submitted.
